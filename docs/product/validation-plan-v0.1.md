# RoleFox v0.1 产品验证计划

- 状态：Accepted Product Baseline
- 版本：v0.1
- 更新日期：2026-09-09

完整的发布阻断场景与验收规则见 [v0.1 P0 Case 验收基线](p0-case-baseline-v0.1.md)。

## 1. 验证目标

v0.1 需要回答的核心问题不是“用户喜不喜欢一个求职 Dashboard”，而是：

> 求职者是否愿意把一条真实求职通道逐步委托给 RoleFox，以及这条通道能否在零虚构、零越权、零重复的前提下，显著减少面试前的日常操作。

验证按“问题是否真实 → 判断是否可靠 → 用户是否信任 → 通道是否可执行 → 是否产生结果”的顺序进行。真实外发动作排在后面，避免在产品价值尚未成立时过早承担平台和账号风险。

## 2. 假设与判定标准

以下目标均是待验证门槛，不是当前产品数据。

| 优先级 | 假设 | 验证方式 | 通过信号 | 未通过时的动作 |
| --- | --- | --- | --- | --- |
| P0 | 高频筛选、重复投递和等待跟进确实消耗大量注意力 | 6–8 位近期活跃求职者访谈，回放最近一周真实流程 | 至少 5 人每周处理 10 个以上机会，且把重复操作列为前三痛点 | 收窄职业或渠道，不进入连接器开发 |
| P0 | 用户能把求职意图表达成可执行规则 | 用用户最近处理过的 20 个岗位做规则回放 | 硬条件覆盖全部明确拒绝原因；剩余模糊项可归入有限异常类别 | 重做 Campaign 配置与规则语言 |
| P0 | 匹配结果值得委托 | 盲评用户近期岗位或合成评估集 | Top 推荐接受率 ≥ 70%；硬条件误放行为 0 | 调整过滤、评分和解释，不开放外发 |
| P0 | 材料在不虚构事实时仍有价值 | 用户审阅至少 30 份岗位材料输出 | ≥ 80% 只需轻微修改；事实错误为 0 | 缩小可生成范围，强化 evidence gate |
| P0 | 用户会从逐次确认迁移到有限委托 | 按 capability 完成已接受的 Shadow、决策样本、L2 动作和异常 Case 门槛 | 超过一半测试者愿意为至少一种能力开启限时 L3 | 保持 L2，研究不信任来源，不把“全自动”写进承诺 |
| P0 | 一条端到端流程可安全闭环 | 合成岗位、Fake Connector、合成消息和测试日历 | 从导入到 `SCHEDULED` 全链路可重复，护栏事件均为 0 | 阻断 Alpha，修复状态、授权或执行一致性 |
| P1 | 大多数日常情况可由策略覆盖 | 对真实历史决策做离线回放，再运行 L2 试用 | ≥ 80% 常规步骤无需新增人工判断 | 优先扩充规则/事实，不增加渠道 |
| P1 | 邮箱和日历足以验证投后闭环 | 连接一个测试邮箱和测试日历 | 常见意图识别与低风险回复覆盖率 ≥ 80%；排期无冲突 | 先提供草稿与交接，不开放自动回复/约面 |
| P1 | 存在可维护的真实岗位和动作路径 | 对候选渠道做条款、权限、稳定性和实现 spike | 至少一个只读源稳定；至少一种受控动作可合规执行或可靠交接 | v0.1 真实渠道保持只读 + 深链接交接 |
| P1 | 首次配置成本可接受 | 5 位未参与设计的测试者完成任务 | 至少 4 人在 20 分钟内完成 Campaign 和 Dry-run，最长不超过 30 分钟 | 简化引导、提供示例和渐进配置 |
| P2 | 托管便利性存在付费空间 | 完成闭环后再做价格与替代方案访谈 | 用户明确愿为常驻运行、连接器维护或协作付费，而非为安全能力付费 | 保持社区项目，不提前开发计费 |

## 3. 研究阶段

### 阶段 A：问题与边界访谈

目的：确认真正浪费时间的环节、现有工作流和不可委托边界。

- 招募 6–8 位过去 3 个月内持续求职的人，优先覆盖不同知识工作岗位。
- 不先展示完整产品概念，先让受访者回放最近一次岗位发现到面试的过程。
- 收集一周内各环节的次数、用时、等待、失败和切换成本。
- 询问“哪一步最不愿交给系统”以及需要什么证据才会授权。
- 只记录去标识化结论；真实简历和聊天记录不得进入公共仓库。

输出：问题排序、不可委托清单、异常分类初稿和候选通道短名单。

### 阶段 B：规则与判断原型

目的：验证用户目标能否成为机器可执行且可理解的策略。

- 用用户近期看过的岗位做离线回放，先由用户独立给出接受、拒绝和原因。
- 再让用户完成 Campaign 配置，比较 RoleFox 的硬过滤、评分和解释。
- 对误判区分为：事实缺失、规则缺失、解析错误、评分权重、解释错误。
- 对材料使用差异审阅：直接接受、轻微修改、重大修改、拒绝、事实错误。

输出：固定评估集、规则覆盖率、Top 推荐接受率、材料修改率和错误分类。

### 阶段 C：Concierge / Wizard-of-Oz 校准

目的：在不进行不可逆自动外发的情况下，验证用户是否愿意真正委托。

- RoleFox 生成 ActionPlan、材料和回复建议，用户逐次确认或修改。
- 产品记录修改原因，但不把单次偏好直接升级为长期规则。
- 达到对应能力的最低校准样本后，展示按能力拆分的 L3 就绪清单和限时授权选项；未达门槛时清楚显示剩余证据。
- 观察用户愿意委托的是发现、材料、投递、跟进、回复还是约面。

输出：委托意愿、授权粒度、异常率、人工操作时间和最常见的不信任原因。

### 阶段 D：受控实地试用

目的：验证一条真实通道的可靠性和结果价值。

- 首先只读同步真实岗位，外发仍在 L2。
- 任何真实外发能力都必须先完成连续 7 天 Shadow；这不是可由样本数替代的条件。
- 匹配/材料各至少积累 50 个决策；投递/回复各至少完成 20 次真实 L2 动作；自动约面至少完成 5 次真实 L2 动作并通过 20 个合成异常 Case。
- 只有未授权、重复、虚构和错误排期均为 0，连接器结果可确认，且用户明确发布版本化授权，才允许对应 capability 进入 L3。
- 用面试是否已双方确认且成功写入日历作为结果终点，不以“点击投递”作为成功。

输出：通道成功率、降级路径、护栏事件、节省时间和合格面试数。

## 4. 核心任务与可用性测试

每位测试者至少完成以下任务：

1. 导入简历，并找到、修改和禁用一条事实。
2. 创建一个包含硬条件、偏好、排除项和每日上限的 Campaign。
3. 解释三个合成岗位为什么被推荐、过滤或升级异常。
4. 审阅一份简历变体，定位每项修改的事实来源。
5. 处理一个“是否仅本次回答，还是更新长期规则”的异常。
6. 查看一个已确认面试，并说出时间、时区、日历状态和所用材料版本。
7. 暂停一类自动动作，再执行全局急停。

观察指标：任务完成率、完成时间、求助次数、误解点、是否能正确复述授权范围。

## 5. 埋点与研究数据

v0.1 只记录理解产品质量所必需的事件，默认本地保存，并允许完整导出和删除。

| 事件 | 用途 | 最少字段 |
| --- | --- | --- |
| `workspace_created` | 衡量首次配置起点 | 时间、版本、语言 |
| `resume_imported` | 识别导入失败 | 格式、结果、耗时，不记录正文 |
| `evidence_confirmed` | 衡量事实准备度 | evidence 类型、状态 |
| `campaign_activated` | 衡量配置完成 | 规则完整度、自动化等级 |
| `dry_run_completed` | 衡量首次价值时间 | 用时、岗位数、异常数 |
| `decision_reviewed` | 衡量匹配质量 | 接受/跳过/修改、原因类别 |
| `material_reviewed` | 衡量材料信任 | 修改级别、事实错误标记 |
| `policy_published` | 衡量委托迁移 | 能力、范围、期限、版本 |
| `action_executed` | 衡量执行可靠性 | 类型、授权方式、结果、耗时 |
| `exception_created` | 衡量人工介入 | 类别、严重度、来源 |
| `exception_resolved` | 衡量恢复效率 | 处理方式、耗时、是否改规则 |
| `interview_scheduled` | 计算北极星 | 是否确认、日历结果、Campaign |
| `kill_switch_used` | 识别信任或安全问题 | 范围、原因类别，不记录敏感正文 |

公共遥测必须是明确选择加入；任何凭证、简历正文、消息正文、联系人、公司内部链接和日历详情都不得进入远程分析。

## 6. 指标口径

### 北极星指标

`ABQI = 活跃用户当月由 RoleFox 推进并最终确认的合格面试数`

“合格”要求同时满足：通过用户硬条件、真实有效、未重复、用户愿意参加、双方时间确认、写入授权日历、无虚假事实和越权动作。

### 关键漏斗

```text
导入岗位
→ 硬条件通过
→ 达到质量阈值
→ 材料可用
→ 已授权执行
→ 外部确认成功
→ 有效回复
→ 已确认面试
```

每层同时报告数量、转化率和中位耗时。不得只展示投递总量。

### 效率与信任

- 每个合格申请所需的用户主动操作分钟数；
- 每个合格面试所需的用户主动操作分钟数；
- 常规步骤无需人工介入的比例；
- Exception 的类别、频率、解决时长和策略更新率；
- 用户修改或拒绝 ActionPlan 的比例；
- L2 到各项 L3 能力的开启、暂停和回退比例。

### 安全护栏

未授权动作、重复投递、虚假事实、硬条件误投、错误排期、敏感数据泄漏均以事件数统计，发布要求始终为 0。

## 7. 决策门

### Gate 1：是否值得继续做完整闭环

进入条件：痛点访谈通过，且规则回放能覆盖主要拒绝原因。

未通过：聚焦单一职业或通道重新验证；暂停真实连接器开发。

### Gate 2：是否可以进入外发校准

进入条件：硬条件误放行为 0、事实错误 0、合成闭环可重复、审计完整。

未通过：所有外发保持 Dry-run。

### Gate 3：是否可以开放真实局部 L3

进入条件：按 capability 同时满足以下门槛，而不是在时间和样本之间二选一：

- 任何真实外发完成连续 7 天 Shadow；
- 匹配/材料各至少 50 个决策；
- 投递/回复各至少 20 次真实 L2 动作；
- 自动约面至少 5 次真实 L2 动作和 20 个合成异常 Case；
- 未授权、重复、虚构和错误排期均为 0；连接器结果可确认；用户主动发布该 capability 的版本化授权。

未通过：v0.1 保持 L2，不影响只读与交接版发布。

### Gate 4：是否继续扩展渠道

进入条件：现有一条通道已证明节省时间，异常率可控，并出现合格面试或明确的领先信号。

未通过：优化核心策略和体验，不增加第二个真实写入连接器。

## 8. 每周产品复盘

每周只回答五个问题：

1. 用户本周少做了哪些操作，节省了多少主动时间？
2. 哪些判断仍频繁要求用户介入，根因是什么？
3. 是否发生任何护栏事件或结果不确定的外部动作？
4. 哪项假设获得了新证据，证据强度如何？
5. 下一周应该删除、收窄还是加强哪个范围？

新增功能必须对应某个未验证假设、反复出现的异常或明确的交付阻塞；否则不进入 v0.1。
