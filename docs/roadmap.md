# RoleFox 能力路线图

路线图服务于一个明确结果：用户设定目标和委托边界后退出日常操作，RoleFox 持续工作到约成合格面试再通知。实现顺序仍是“先形成可信闭环，再提高自动化等级”，避免用海投冒充自治能力。

> M1–M5 是能力成熟度地图，不是必须按模块全部做完的日历阶段。v0.1 会从每个阶段抽取最薄的一层，按纵向切片优先跑通一条完整通道；实施周次、发布门槛和止损规则以 [v0.1 交付计划](product/delivery-plan-v0.1.md) 为准。

- [x] 等待回复、到期跟进和面试排期状态边界
- [x] dry-run、急停、等级、敏感话题与限额的策略判断规则及单元测试
- [x] 按能力拆分的连接器基础契约
- [x] 厂商无关的 AI Provider 基础契约
- [x] Workspace / CandidateProfile / SearchCampaign 领域边界
- [x] 首份产品北极星决策记录（[ADR-0001](adr/0001-pre-interview-autopilot.md)）

## M1：通用单用户基础

目标：一位新用户无需修改代码，即可建立私有工作区并导入第一批岗位。

- 引导式初始化：语言、时区、币种和通知偏好
- 候选人事实库与证据来源管理
- 每个 Workspace 最多一个 `CALIBRATING` / `ACTIVE` SearchCampaign；历史 Campaign 可只读 `LISTENING`
- 委托策略初始化：质量阈值、排除条件、节奏、答案范围和通知规则
- SQLite 存储、版本化 schema 和迁移
- CSV / JSON 岗位导入、手动链接和合成演示连接器
- 标准化职位、地点、工作方式、雇佣类型和薪酬
- 工作区完整导出、备份和删除；落实 90 天原文、1 年结构化历史/最小审计、30 天滚动备份保留期
- Docker Compose 在 macOS/Windows/Linux 的正式安装验证；macOS 原生开发正式支持

完成标准：使用两组完全不同的合成候选人配置完成相同流程，核心代码无改动。

## M2：可解释岗位匹配

目标：减少无效浏览，同时让用户理解和纠正推荐结果。

- 硬条件过滤；同源 externalId/规范 URL 精确去重；跨来源疑似重复组人工消歧
- 可配置权重的分项评分
- 推荐理由、风险点和缺失信息
- 用户接受 / 跳过 / 不感兴趣反馈
- 自动投递质量阈值和公司、岗位冲突检查
- 评分版本、模型版本与评估集
- 首个只读真实岗位来源（优先官方 API 或用户导入）

完成标准：在固定合成评估集上可重复评分；每个推荐都有理由和数据来源。

## M3：事实驱动的材料自动化

目标：基于候选人的真实事实自动生成岗位定制材料，并通过一段校准期建立用户信任。

- 简历版本与结构化履历
- JD 对齐建议、简历差异预览和事实校验
- 求职信、招呼语和常见问答草稿
- 多语言内容与可替换 AI Provider
- 材料模板与版本历史
- 敏感问题和低置信度内容自动升级人工
- L2 校准反馈：学习用户保留、修改和拒绝材料的原因

完成标准：生成内容中的事实声明均能关联 evidence ID；用户可查看、编辑和拒绝每项改动。

## M4：投递 Autopilot

目标：用户批准一套版本化委托策略后，RoleFox 能对达到质量门槛的岗位完成合规、可审计、不会重复的自动投递。

- L2 逐次审批与 L3 版本化委托授权
- 按 capability 的 L3 门槛：真实外发连续 7 天 Shadow；匹配/材料 50 个决策；投递/回复 20 次真实 L2；自动约面 5 次真实 L2 + 20 个合成异常 Case；四类严重错误为 0
- 匹配阈值、黑白名单、默认上限（投递 10/日、回复 8/小时、约面 3/日）、普通配置硬上限（25/12/8）和同公司岗位冲突规则
- 内容哈希、过期时间、幂等键和重试策略
- 本地 Runner 与凭证隔离
- 审计事件和脱敏执行结果
- 第一个经过条款与权限审查的投递连接器
- 连接器兼容性矩阵、限速和健康状态

完成标准：L3 授权范围内的高质量岗位无需逐次操作即可完成投递；规则外岗位、过期计划、内容变化、急停或重复请求全部失败关闭或进入异常队列。

## M5：沟通、跟进与自动约面

目标：RoleFox 接管投递后的等待、跟进、初聊和排期，直到面试确认成功再把流程交回用户。

- 邮件或官方消息源同步
- 无回复跟进的冷却时间、每个 Application 最多一次自动跟进和停止条件
- 基于事实库、已批准答案及区间的自动回复
- 超出答案范围、事实缺失或敏感承诺自动转人工
- 一个日历 Provider 账户、一个写入日历、同账户多个 busy calendar、版本化排期预授权
- 面试时间提取、时区消歧、冲突检测和自动确认
- calendar-first 私有 tentative event Saga；日历/回复独立 Operation；补偿失败或未知进入 `SEV-1` 并暂停约面
- 自动确认同时占用回复限额，并受独立的每日约面上限约束
- 产品内 Inbox 强制保留事实、邮件默认外部通知、Webhook 可选；第二个必需外部备用渠道延期至 P1
- 面试成功通知、核心事实准备包、求职漏斗与面试复盘；AI 面试建议延期至 P1

完成标准：所有业务外发动作都经过策略判断；隔离 SafetySignal 只接受固定 schema、预配置目标和窄化授权。L3 只在回复有依据、时间明确、日历无冲突且位于有效授权窗口时自动执行。进入 `SCHEDULED` 后立即通知用户；异常只进入一个统一收件箱，不要求用户重新接管整条流程。

## 持续工作

- 威胁建模、依赖更新、漏洞响应和隐私审查
- 中英文文档、无障碍和国际化
- 连接器 SDK 兼容性与示例项目
- 合成数据集、回归评估和可观察性
- 社区治理、发布节奏和贡献者体验

## 暂不排期

- 招聘方 ATS 或人才库
- 无人值守海投
- CAPTCHA 或反自动化绕过
- 候选人数据交易
- 在缺少实际维护能力时同时承诺大量招聘平台
- PostgreSQL、跨数据库迁移和第二存储实现
- 跨日历 Provider 账户聚合和向招聘方发送日历邀请
