# RoleFox 路线图

路线图按“先形成通用闭环，再提高自动化等级”排序。版本日期由真实验证速度决定，不用虚假的固定期限换取进度感。

## M0：产品与安全地基（当前）

目标：让项目的产品边界、核心状态和安全规则可以被讨论和测试。

- [x] 开源仓库、许可证、贡献与安全政策
- [x] 产品工作台演示（仅合成数据）
- [x] 申请状态机与非法迁移测试
- [x] dry-run、急停、等级、敏感话题与限额的策略判断规则及单元测试
- [x] 按能力拆分的连接器基础契约
- [x] 厂商无关的 AI Provider 基础契约
- [x] Workspace / CandidateProfile / SearchCampaign 领域边界
- [ ] 决策记录（ADR）和公开版本变更记录

完成标准：`pnpm check` 通过；公共材料不含个人化默认值；README 能准确区分已实现与计划能力。

## M1：通用单用户基础

目标：一位新用户无需修改代码，即可建立私有工作区并导入第一批岗位。

- 引导式初始化：语言、时区、币种和通知偏好
- 候选人事实库与证据来源管理
- 可创建、暂停和归档的 SearchCampaign
- SQLite 存储、版本化 schema 和迁移
- CSV / JSON 岗位导入、手动链接和合成演示连接器
- 标准化职位、地点、工作方式、雇佣类型和薪酬
- 工作区完整导出、备份和删除

完成标准：使用两组完全不同的合成候选人配置完成相同流程，核心代码无改动。

## M2：可解释岗位匹配

目标：减少无效浏览，同时让用户理解和纠正推荐结果。

- 硬条件过滤与重复岗位合并
- 可配置权重的分项评分
- 推荐理由、风险点和缺失信息
- 用户接受 / 跳过 / 不感兴趣反馈
- 评分版本、模型版本与评估集
- 首个只读真实岗位来源（优先官方 API 或用户导入）

完成标准：在固定合成评估集上可重复评分；每个推荐都有理由和数据来源。

## M3：材料工作台

目标：基于候选人的真实事实，为目标岗位准备可审核材料。

- 简历版本与结构化履历
- JD 对齐建议、简历差异预览和事实校验
- 求职信、招呼语和常见问答草稿
- 多语言内容与可替换 AI Provider
- 材料模板与版本历史
- 敏感问题和低置信度内容自动升级人工

完成标准：生成内容中的事实声明均能关联 evidence ID；用户可查看、编辑和拒绝每项改动。

## M4：受控投递

目标：完成第一条合规、可审计、不会重复执行的真实投递链路。

- 审批中心与一次性授权
- 内容哈希、过期时间、幂等键和重试策略
- 本地 Runner 与凭证隔离
- 审计事件和脱敏执行结果
- 第一个经过条款与权限审查的投递连接器
- 连接器兼容性矩阵、限速和健康状态

完成标准：未经批准、计划过期、内容被修改、急停开启或重复请求时，执行全部失败关闭。

## M5：沟通与面试

目标：把投递后的消息、决定和日程纳入同一个可控闭环。

- 邮件或官方消息源同步
- 基于已批准答案库的回复建议
- 敏感承诺自动转人工
- 面试时间提取、冲突检测和确认
- 邮件、通用 Webhook 等可替换通知渠道
- 求职漏斗与面试复盘

完成标准：所有外发回复都经过策略判断；除符合预批准 L3 规则外均须逐次审批，日程冲突不会被自动确认。

## 持续工作

- 威胁建模、依赖更新、漏洞响应和隐私审查
- 中英文文档、无障碍和国际化
- 连接器 SDK 兼容性与示例项目
- 合成数据集、回归评估和可观察性
- 社区治理、发布节奏和贡献者体验

## 暂不排期

- 招聘方 ATS 或人才库
- 无人值守海投
- CAPTCHA 或反自动化绕过
- 候选人数据交易
- 在缺少实际维护能力时同时承诺大量招聘平台
