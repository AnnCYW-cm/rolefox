# ADR-0001：以面试前 Autopilot 为产品北极星

- 状态：Accepted
- 日期：2026-09-08

## 背景

招聘平台完成了企业与候选人的信息连接，但岗位浏览、资格判断、打招呼、材料调整、投递、跟进和约时间仍由候选人逐项完成。大量消息没有回复，候选人的注意力被重复操作占用，却不必然转化为更多合格面试。

如果 RoleFox 只把这些点击做得更快，它仍然要求用户持续盯着流程，无法解决真正的问题。

## 决策

RoleFox 的目标形态是一个受规则约束的候选人侧自主求职智能体。用户只需要：

1. 提供真实且可追溯的履历事实；
2. 设定求职目标和可撤销的版本化委托边界；
3. 收到已确认的面试通知后参加面试。

从岗位发现到 `SCHEDULED` 的日常执行由 RoleFox 接管。系统采用 **Policy as Authorization**：

- 新用户默认从 `L2 + DRY_RUN` 开始校准；
- 稳定后进入有边界的 `L3 Autopilot`，授权内动作不要求逐次点击；
- 事实缺失、规则越界、授权失效、时间歧义、日历冲突或高风险承诺进入统一异常队列；
- Offer、法律声明、无法核实的身份或经历，以及 CAPTCHA/访问控制绕过不属于可委托范围；
- 无规则的 L4 无人值守模式保持关闭。

产品北极星指标是：每位活跃求职者每月由 RoleFox 在无需日常人工介入的情况下约到的合格面试数（ABQI）。投递量不是成功指标。

## 影响

- 申请状态不包含人工审批阶段；审批与策略授权属于独立的 ActionPlan 生命周期。
- Web 稳定态的核心是进度、已约面通知和异常收件箱，不是逐项审批列表。
- 系统需要可持续运行的 Worker、可替换连接器、版本化委托策略、幂等执行与完整审计。
- 自动约面必须把回复、日历账户、授权窗口、空闲快照和具体时段绑定为一个可验证的复合动作。
- 所有路线图决策优先减少候选人的日常介入，同时用越权数、虚假陈述数和转化率作为护栏。

## 不采用的方案

- **纯推荐或看板工具**：仍要求用户自己筛选和推动流程。
- **所有动作逐次审批**：适合校准期，不是最终产品体验。
- **无条件批量海投**：会损害申请质量、账号安全和项目可信度。
