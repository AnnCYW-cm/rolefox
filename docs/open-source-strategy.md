# RoleFox 开源策略

## 开源承诺

RoleFox 的开源版本应当始终是一个完整可用的单用户求职产品，而不是托管服务的阉割试用版。以下能力属于开源核心：

- 候选人资料、事实证据和求职计划管理
- 岗位导入、标准化、去重和匹配
- 材料生成、委托授权、异常审批、策略与审计
- 本地存储、导出、删除和自托管
- 连接器与 AI Provider SDK
- 至少一个合成连接器和可重复测试数据
- CSV / JSON、手动链接，以及至少一条无需专有托管服务即可真实使用的开放导入链路

官方维护的连接器原则上也应开源；如果某个平台的授权协议明确禁止公开实现或要求专有托管组件，必须在兼容性矩阵中说明原因、数据流和替代方案，不能把它伪装成开源核心能力。

## 可能的未来托管服务

如果社区和真实使用证明有需求，可以提供可选的商业托管服务，例如：

- 免运维部署、升级、备份和加密同步
- 托管模型、通知和经过维护的连接器
- 多设备使用、职业教练协作和团队策略
- 企业级可观察性、支持与服务保障

托管服务销售的是便利性、运维和协作，不是用户数据。自托管用户必须能导入、导出和删除自己的完整数据。

## 不可妥协的边界

- 不出售候选人数据，不用个人求职数据做广告定向。
- 不接受付费职位改变自然匹配排序而不披露。
- 不把安全策略、数据导出或账号删除放进付费墙。
- 不通过闭源服务迫使连接器、模型或通知渠道锁定单一厂商。
- 不以增长为理由放宽授权边界、限速、审计或平台合规要求。

## 许可证现状

项目当前采用 Apache License 2.0。它对个人、公司和集成方友好，包含专利授权，但也允许第三方修改后提供商业托管服务。

这是采用速度与商业防御之间的明确取舍，不应假装不存在。在外部贡献者显著增加之前，维护者需要公开决定：

1. 是否继续 Apache-2.0；
2. 是否需要商标政策来保护 RoleFox 名称与官方发行版；
3. 项目决策权、版本发布和安全响应如何治理；
4. 官方托管服务与社区版本如何保持透明边界。

许可证变更不能追溯性地重新授权已有外部贡献，因此相关决策应尽早、公开完成。
