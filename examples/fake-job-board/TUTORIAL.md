# 用合成岗位完成一次本地校准

本教程适用于 RoleFox `0.1.0-alpha.4`。Alpha.4 将 Alpha.3 的 UI 重做为 Signal Desk：采用冷石墨黑、雾白与电光狐橙、几何负形狐标、桌面设置栏和连续“机会排序”账本；移动端提供底部任务导航，并在已有岗位时优先呈现结果。操作能力、浏览器本地数据 schema 和安全边界均未改变；Alpha.3 保持为不可变的历史发布。全部操作仍在当前浏览器完成；页面没有账号、云同步、后台扫描、岗位抓取、投递或回复功能。

## 1. 打开 Alpha

打开已经发布的 RoleFox Alpha 页面，或在仓库根目录执行：

```bash
pnpm install --frozen-lockfile
pnpm dev
```

本地运行时访问 `http://localhost:3000`。如果浏览器阻止 `localStorage`，页面会锁定编辑，避免让你误以为数据已经保存。

## 2. 配置合成规则

打开 [`rules.json`](rules.json)，在 Signal Desk 的“设置筛选偏好”区域手工填写目标职位与目标地点，再展开“高级规则”填写关键词：

- 目标职位：`产品经理`
- 目标地点：`远程`
- 加分关键词：`AI，工作流，B2B`
- 硬排除关键词：`销售，区块链，Web3`

点击“保存并重新评分”。保存成功后高级规则会折叠，以便更快进入岗位与结果；规则文件目前不能直接上传，它只是可复制、可复查的示例。

## 3. 粘贴岗位

打开 [`jobs.paste.txt`](jobs.paste.txt) 并复制全部 12 行。在“添加岗位”设置区展开“批量粘贴”，粘贴后点击“检查并导入”。桌面上设置区位于结果列表旁；移动端可用底部的“规则 / 岗位 / 结果”导航快速切换，已有岗位时“机会排序”会优先显示。

当前批量入口只接受以下格式之一：

```text
职位 | 公司 | 地点 | 描述
```

也可以用全角竖线或制表符分隔。一次最多粘贴 100 个非空行，当前浏览器最多保存 500 个岗位。页面没有 CSV/JSON 岗位文件导入功能，所以：

- `jobs.csv` 不能直接粘贴或上传；
- `jobs.json` 不能通过“从备份恢复”导入；
- 若要复现本教程，请使用 `jobs.paste.txt`。

## 4. 检查可解释结果

导入成功后应在连续结果列表中看到 12 个岗位。列表会按确定性分数排序，并分别显示命中的职位方向、地点、加分词和未命中的条件。

重点检查：

- “企业软件销售经理”应命中 `销售`，进入“已被硬规则排除”；
- “Web3 产品经理”应命中 `Web3` 与 `区块链`，进入“已被硬规则排除”；
- 地点、职位方向或加分词没有命中时只会显示关注项，不等同于硬排除；
- 分数是当前 Alpha 的规则排序结果，不是录用概率，也不会触发投递。

## 5. 做出校准选择

逐个选择“感兴趣”或“不感兴趣”。选择只记录在当前浏览器，用来比较规则分数与你的真实判断；再次点击相同选项可撤销。

建议至少检查一个高分岗位、一个低分岗位和两个硬排除岗位。如果排序与你的判断不一致，回到规则区域调整关键词并重新评分。

## 6. 导出或清除

在“导出、备份或彻底清除”中：

- “导出完整备份”会下载规则、岗位正文和选择，文件可能包含敏感内容，请自行妥善保管；
- “导出无原文汇总”只包含数量、分数区间、选择统计和规则形态，不包含规则原文、公司、地点或岗位正文；
- “从备份恢复”只接受 RoleFox 自己生成且结构、版本均有效的完整导出；
- “清除当前浏览器数据”会永久移除本地记录，服务器没有副本可恢复。

请勿把真实简历、联系人、邮箱、聊天记录、凭证或岗位正文提交到公开 GitHub Issue。反馈只描述问题类型、预期行为，或附上本目录的合成样本。

## 示例数据的证据边界

本目录所有内容都是合成测试资料。完成本教程不代表通过真实用户研究、连接器验证、真实 Provider 验收或任何发布 Gate。
