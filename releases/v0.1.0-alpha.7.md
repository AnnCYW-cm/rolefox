# RoleFox v0.1.0-alpha.7

[中文](#中文) · [English](#english)

发布日期 / Release date: **2026-09-23**

## 中文

v0.1.0-alpha.7 将对 v0.1.0-alpha.6 的完整视觉与响应式界面重做，和随后完成的本地复核能力合并为一次正式发布。RoleFox 仍是浏览器本地运行的开源岗位判断与校准工具；本版把 Fox Ledger 重构为 **Clear Signal / 明亮信号工作台**，并加入本地文件预览导入、重复检查、岗位编辑、搜索与筛选，以及感兴趣岗位导出。

### Clear Signal / 明亮信号工作台

- 以冷白、石墨和稀缺狐橙取代暖纸色与编辑台账式呈现，让狐橙只承担品牌和关键状态信号；
- 使用 64px 单层 app bar 统一品牌、任务导航与浏览器本地状态，减少首屏重复层级；
- 以连续结果账本和独立输入坞组织核心工作流，让查看、判断与录入保持清晰关系；
- 移除核心工作区的卡片堆叠与浮动阴影，改用留白、排版和克制分割表达结构；
- 移除超小字号并提高辅助信息的可读性，保留明确标签和渐进披露；
- 保留可见键盘焦点、主内容跳转、语义区域、读屏提示、弹窗焦点循环、Escape 取消、触发点焦点返回和 reduced-motion 行为。

仓库自动化检查继续覆盖文档、验证登记、lint、类型检查、静态构建、组件测试和 verification 测试。

### 本地导入、去重与复核

- 从本地选择 CSV 或 JSON 岗位文件后先解析并显示预览，只有用户确认选中的记录才会写入；文件不会上传；
- 精确重复会同时对照现有岗位和同一导入文件检查，并且不能被选中；相同职位、公司和地点但描述不同的记录标为“疑似重复”，默认跳过，复查后可主动选择；
- 可以编辑已有岗位并立即按当前规则重新评分；若修改会造成精确重复则拒绝保存，若命中疑似重复则要求再次确认；
- 可以搜索职位、公司、地点或描述，并在全部、待决定、推荐、感兴趣、不感兴趣和已排除六种筛选间切换；
- 可以把所有标记为“感兴趣”的岗位导出为 JSON，包含岗位原文、当前分数、标签、资格状态、命中理由与风险提示；
- 岗位导入文件、备份恢复文件和序列化本地状态均有 15 MB 安全上限。超限时拒绝读取或写入，不覆盖已有本地数据。

### 兼容性与历史边界

确定性评分与排序、规则、合成样例、校准选择、完整备份、无原文汇总、恢复、逐项删除、彻底清除和失败关闭原则保持不变。存储键、版本化数据 schema 和既有数据校验规则也没有变化；已有 Alpha.1–Alpha.6 本地数据无需迁移，仍可读取。

Alpha.7 沿用 Alpha.6 的安全边界，没有账号、服务端存储、云同步、自动抓取、真实平台连接、AI 调用、材料生成、自动投递、消息回复、邮箱或日历连接，也不会采取任何外部动作。

v0.1.0-alpha.6 作为已经发布的历史版本保持不可变。Alpha.7 不会追溯修改 Alpha.6 的标签、版本说明、Changelog 记录、验证制品或当时的范围陈述。

[在线体验](https://anncyw-cm.github.io/rolefox/)只需要现代浏览器，不需要注册账号。也可以跟随[合成样例教程](../examples/fake-job-board/TUTORIAL.md)完成一次本地校准。界面和仓库示例教程目前为中文。

## English

v0.1.0-alpha.7 combines the complete visual and responsive-interface rebuild of v0.1.0-alpha.6 with the local review capabilities completed afterward. RoleFox remains an open-source, browser-local job-triage and calibration tool. This release rebuilds Fox Ledger as **Clear Signal** and adds local-file import preview, duplicate review, job editing, search and filtering, and an interested-jobs export.

### Clear Signal

- Replaced the warm-paper editorial treatment with cool white, graphite, and a scarce fox-orange accent, reserving orange for brand and critical state signals.
- Unified product identity, task navigation, and browser-local status in a single 64px app bar, reducing repeated first-screen hierarchy.
- Organized the core workflow around a continuous result ledger and a dedicated input dock so reviewing, deciding, and adding jobs remain clearly related.
- Removed stacked-card composition and floating shadows from the core workspace, using spacing, typography, and restrained rules to express structure.
- Removed ultra-small interface text and improved the readability of supporting information while preserving explicit labels and progressive disclosure.
- Preserved visible keyboard focus, skip navigation, semantic regions, screen-reader cues, modal focus cycling, Escape cancellation, trigger focus return, and reduced-motion behavior.

Repository automation continues to cover documentation, verification registry checks, linting, type checking, the static build, component tests, and verification tests.

### Local import, deduplication, and review

- A selected local CSV or JSON job file is parsed and previewed first. Only records explicitly selected and confirmed by the user are written, and the file is never uploaded.
- Exact duplicates are checked both against existing jobs and within the same import file and cannot be selected. Records with the same title, company, and location but different descriptions are marked as possible duplicates, skipped by default, and can be selected after review.
- Existing jobs can be edited and immediately rescored against the current rules. An edit that would create an exact duplicate is refused; a possible duplicate requires a second confirmation.
- Search covers title, company, location, and description, with six filters: all, undecided, recommended, interested, not interested, and excluded.
- All jobs marked interested can be exported as JSON with the job text, current score, label, eligibility, reasons, and concerns.
- Job-import files, backup-restore files, and serialized local state have a 15 MB safety limit. Over-limit reads or writes are refused without overwriting existing local data.

### Compatibility and historical boundary

Deterministic scoring and ordering, rules, synthetic examples, calibration decisions, full backup, the no-text aggregate, restore, per-job deletion, full clearing, and fail-closed principles remain unchanged. The storage key, versioned data schema, and existing data-validation rules are also unchanged; existing Alpha.1–Alpha.6 local data require no migration and remain readable.

Alpha.7 keeps Alpha.6's safety boundary. It has no accounts, server storage, cloud sync, automatic scraping, real-platform connections, AI calls, material generation, automatic applications, message replies, mailbox access, or calendar access, and it takes no external actions.

v0.1.0-alpha.6 remains an immutable historical release. Alpha.7 does not retroactively alter the Alpha.6 tag, release notes, changelog record, verification artifacts, or scope statements published at that time.

The [live tool](https://anncyw-cm.github.io/rolefox/) needs only a modern browser and no account. You can also complete a local calibration with the [synthetic example tutorial](../examples/fake-job-board/TUTORIAL.md). The interface and repository example tutorial are currently in Chinese.

The release workflow accepts only a tagged commit contained in protected `main` history and produces a GitHub Actions OIDC provenance attestation for the static build.

```

```

### Capability and research boundary

Every added capability runs in the current browser and requires an explicit user action. It makes no AI call, connects to no job platform, and takes no external action. Scores still represent local rules only and do not predict job quality, hiring outcomes, or career fit; import, editing, filtering, and export do not change the browser-local data schema, storage key, or safety boundary.

Pre-W1 Gate 1 remains `BLOCKED_NOT_STARTED`. The Clear Signal rebuild, local-review capabilities, automated checks, publication, and synthetic data are not user-research evidence and change no verification state. Gate 1 decides only whether and how to begin the later productization W1; it does not block this narrowly scoped open-source release.
