# RoleFox v0.1.0-alpha.8

[中文](#中文) · [English](#english)

发布日期 / Release date: **2026-09-24**

## 中文

v0.1.0-alpha.8 是一次**浏览器验证与发布可靠性版本**。RoleFox 继续是浏览器本地运行的开源岗位判断与校准工具；本版完整沿用 Alpha.7 的 Clear Signal 界面与产品流程，只增加针对实际静态构建的可重复 Chromium 端到端验证、阻断 CI 与正式发布的自动化 Gate，以及 GitHub Pages 部署后的线上验收。

### 七条 Playwright Chromium 流程

自动浏览器套件在隔离的浏览器上下文中使用合成数据，覆盖现有 Alpha.7 关键旅程：

1. 首屏任务、当前版本、本地隐私说明和无外部动作边界；
2. 职位、公司、地点与描述搜索，以及全部、待决定、推荐、感兴趣、不感兴趣和已排除六类筛选；
3. 手工新增岗位、刷新后持久化、人工决定、岗位编辑、重新评分和再次刷新；
4. CSV 导入预览中的现有精确重复、疑似重复与文件内重复处理；
5. JSON 导入预览默认选择新岗位并跳过文件内重复；
6. 感兴趣清单下载及其岗位原文、分数、资格状态和当前评分依据；
7. 完整备份下载、确认清空、确认恢复，以及规则、岗位和人工决定在刷新后的持久化。

这些流程验证既有行为，不引入浏览器自动操作产品能力，也不读取真实用户数据或访问真实招聘平台。

### 静态构建与发布 Gate

- 新增 Node 静态 export harness；本地与自动化 E2E 都针对 `apps/web/out` 运行，与正式发布包使用同一份生成站点；
- CI 在既有仓库检查之后运行完整浏览器套件，失败会阻止合并检查通过；
- Alpha 标签发布在打包与 provenance attestation 之前运行同一套完整 E2E，失败不会生成 Release；
- GitHub Pages 部署完成后，使用部署输出的实际 base path 执行线上 smoke test，检查当前版本、首屏任务和浏览器本地隐私边界；
- 失败运行会上传 Playwright HTML 报告、trace、截图和测试结果，便于复现与诊断。

### 兼容性、安全与历史边界

Alpha.8 不新增产品能力，也不改变 UI、文案流程、确定性评分与排序、规则、合成样例、导入与去重、岗位编辑、搜索与筛选、校准决定、导出与恢复、数据 schema、存储键、15 MB 上限、校验行为或失败关闭原则。Alpha.1–Alpha.7 浏览器本地数据无需迁移。

本版仍没有账号、服务端存储、云同步、自动抓取、后台收集、真实平台连接、AI 调用、材料生成、自动投递、消息回复、邮箱或日历连接，也不会采取任何外部动作。

v0.1.0-alpha.7 作为已经发布的历史版本保持不可变。Alpha.8 不会追溯修改 Alpha.7 的标签、版本说明、Changelog 记录、验证制品或当时的范围陈述。

[在线体验](https://anncyw-cm.github.io/rolefox/)只需要现代浏览器，不需要注册账号。也可以跟随[合成样例教程](../examples/fake-job-board/TUTORIAL.md)完成一次本地校准。界面和仓库示例教程目前为中文。


### 能力与研究边界

自动浏览器检查是现有开源工具的发布可靠性证据，不是用户研究、真实岗位数据、连接器验收或产品化能力证据。Playwright 覆盖也只声明上述 Chromium 流程通过，不代表所有浏览器、平台或未覆盖行为都已得到验证。

Pre-W1 Gate 1 保持 `BLOCKED_NOT_STARTED`。Alpha.8 的 E2E、发布 Gate、Pages smoke、上线事实和合成数据都没有改变任何研究验证状态；Gate 1 只用于决定是否、以及如何启动下一阶段产品化 W1，不阻止这一窄范围开源工具发布。

## English

v0.1.0-alpha.8 is a **browser-verification and release-reliability release**. RoleFox remains an open-source, browser-local job-triage and calibration tool. This version keeps Alpha.7's Clear Signal interface and product workflow intact and adds repeatable Chromium end-to-end verification against the actual static build, with automated gates for CI and formal releases plus post-deployment verification for GitHub Pages.

### Seven Playwright Chromium journeys

The automated browser suite uses synthetic data in isolated browser contexts and covers the existing Alpha.7 critical journeys:

1. The initial tasks, current version, local-privacy disclosure, and no-external-action boundary.
2. Search across title, company, location, and description, plus all, undecided, recommended, interested, not interested, and excluded filters.
3. Manual job entry, persistence after reload, a user decision, job editing, rescoring, and another reload.
4. Existing exact duplicates, possible duplicates, and within-file duplicates in the CSV import preview.
5. Default selection of new jobs and skipping of within-file duplicates in the JSON import preview.
6. The interested-jobs download and its job text, score, eligibility, and current scoring evidence.
7. Full-backup download, confirmed clearing, confirmed restore, and persistence of rules, jobs, and user decisions after reload.

These journeys verify existing behavior. They do not add browser-automation capability to the product, read real user data, or visit real job platforms.

### Static build and release gates

- A Node static-export harness makes local and automated E2E runs exercise `apps/web/out`, the same generated site used by the formal release package.
- CI runs the full browser suite after the existing repository checks, and a failure prevents the check from passing.
- Tagged Alpha releases run the same full E2E suite before packaging and provenance attestation; a failure prevents the Release from being produced.
- After GitHub Pages deployment, a live smoke test uses the deployment output's actual base path and checks the current version, initial tasks, and browser-local privacy boundary.
- Failed runs upload the Playwright HTML report, trace, screenshots, and test results for reproduction and diagnosis.

### Compatibility, security, and historical boundary

Alpha.8 adds no product capability and changes no UI, copy flow, deterministic scoring or ordering, rules, synthetic examples, import or deduplication behavior, job editing, search or filtering, calibration decisions, export or restore behavior, data schema, storage key, 15 MB limit, validation behavior, or fail-closed principle. Alpha.1–Alpha.7 browser-local data require no migration.

This release still has no accounts, server storage, cloud sync, automatic scraping, background collection, real-platform connections, AI calls, material generation, automatic applications, message replies, mailbox access, or calendar access, and it takes no external action.

v0.1.0-alpha.7 remains an immutable historical release. Alpha.8 does not retroactively alter the Alpha.7 tag, release notes, changelog record, verification artifacts, or scope statements published at that time.

The [live tool](https://anncyw-cm.github.io/rolefox/) needs only a modern browser and no account. You can also complete a local calibration with the [synthetic example tutorial](../examples/fake-job-board/TUTORIAL.md). The interface and repository example tutorial are currently in Chinese.

### Download and provenance

In addition to GitHub's source archives, the Release provides a `rolefox-web-v0.1.0-alpha.8.tar.gz` static build and its SHA-256 file. The release workflow accepts only a tagged commit contained in protected `main` history and produces a GitHub Actions OIDC provenance attestation for the static build.

With the [GitHub CLI](https://cli.github.com/) installed, verify the downloaded artifact from its directory:

```bash
gh attestation verify rolefox-web-v0.1.0-alpha.8.tar.gz --repo AnnCYW-cm/rolefox
```

After extracting it, serve the directory with any static web server. For example, with Python 3 available locally:

```bash
tar -xzf rolefox-web-v0.1.0-alpha.8.tar.gz
python3 -m http.server 8000 --directory rolefox-web-v0.1.0-alpha.8
```

### Capability and research boundary

Automated browser checks are release-reliability evidence for the existing open-source tool, not user research, real-job data, connector acceptance, or evidence of productized capability. Playwright coverage means only that the Chromium journeys listed above pass; it is not a claim that every browser, platform, or uncovered behavior has been verified.

Pre-W1 Gate 1 remains `BLOCKED_NOT_STARTED`. Alpha.8's E2E suite, release gates, Pages smoke test, publication, and synthetic data change no research-verification state. Gate 1 decides only whether and how to begin the later productization W1; it does not block this narrowly scoped open-source release.
