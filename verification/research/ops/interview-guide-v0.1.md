# Pre-W1 访谈与规则回放提纲 v0.1

- 版本：`pre-w1-interview-guide-v0.1`
- 目标：先验证问题，再验证规则；避免产品展示和诱导性提问污染回答

主持前确认同意、cohort-local surrogate、系统时间和受控存储。不要在共享屏幕、录屏或笔记中暴露邮箱、日历、凭证、完整姓名或无关个人信息。

## 1. 开场

1. 重申研究目的、自愿参加、可跳题和退出方式。
2. 确认是否录音；未明确同意时只做结构化笔记。
3. 说明“没有正确答案”，请以最近真实经历回答。
4. 在痛点问题完成前不展示 RoleFox、不描述自动化方案、不询问购买意愿。

## 2. 最近一周流程回放

按时间顺序询问，先开放提问，再用固定追问补全：

1. 最近一次开始找岗位时，从哪里开始？
2. 最近一周大约处理了多少个独立机会？只记录计数，不记录公司或 URL。
3. 对每类机会做了哪些步骤：发现、筛选、核实、材料、投递、跟进、沟通、排期？
4. 哪些步骤重复最多？哪些最耗注意力？
5. 请把主要痛点排序。主持人记录固定 pain code 和排名；原话只留受控 raw note。
6. 最近一次放弃、跳过或拒绝一个岗位的明确原因是什么？继续追问直到参与者表示没有其他明确拒绝原因。
7. 哪些判断可以写成稳定规则？哪些必须每次人工判断？
8. 哪类错误最不可接受？发生时希望系统停止、询问还是只提醒？

不得把“每周 10 个机会”或“前三痛点”门槛告诉参与者后再让其调整答案。

## 3. 委托边界

依次询问并使用 rubric code：

- 哪些动作永远不愿交给工具？
- 哪些动作只愿逐次确认？
- 哪些动作在明确规则、限额和审计下可以限时自动执行？
- 哪些事实或承诺必须始终由本人确认？
- 哪些异常必须立即停止整条流程，哪些只暂停单一 capability？

这里收集边界，不把“愿意自动化”解释为已授权真实外发。

## 4. Target-channel feasibility

仅对相应 cohort 按固定顺序确认：

1. 当前仍在求职；
2. 申请主要在线完成；
3. 招聘沟通可到达本人使用的邮箱；
4. 在未来另行同意且可随时撤销的测试中，愿意连接一个真实隔离邮箱；
5. 在未来另行同意且可随时撤销的测试中，愿意连接一个真实日历 Provider。

每项只编码 `YES / NO / UNKNOWN`。不要在 Pre-W1 实际连接账号，不收 provider 名、邮箱地址、日历内容或凭证。

## 5. 规则回放

仅在 pain threshold 编码完成且参与者合格、规则回放同意有效、20-job manifest 已冻结后执行：

1. 记录 `replay_started_at`，验证它严格晚于 dataset `frozen_at`。
2. 按冻结顺序逐个展示 20 个岗位，不替换、不跳过；发生技术问题时记录 interruption。
3. 在展示任何系统判断前，让参与者独立选择 `ACCEPT / REJECT / NEEDS_REVIEW` 并选择已有 reason code；新理由先记为 `UNMAPPED_PENDING_CODE`。
4. 让参与者解释该决定能否表达为硬规则、排序偏好或有限异常。
5. 完成全部 20 个后再运行规则并比较，不在中途调参。
6. 对每个明确拒绝理由记录是否被硬规则覆盖；对剩余模糊项记录固定 exception category 或 `UNBOUNDED`。
7. 若中途退出、数据集 digest 改变或未完成 20 个，结果必须为 `INCONCLUSIVE`，不得补换岗位后沿用原 dataset ID。

## 6. 收尾

1. 询问是否有未覆盖的重要边界；不把新增内容直接改成 PASS。
2. 重申退出方式和保留期限。
3. 记录 session 完成时间、protocol deviation、可选后续联系选择。
4. 将自由文本/录音关闭并移入受控存储；完成结构化 observation 后执行去标识复核。
